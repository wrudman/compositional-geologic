Tool use and atomic complexity

Qwen3.5-9B · thinking on · 32,768 tokens per request · 74 paired items · optional tools versus no tools.

For each question type, one question–diagram pair was generated at every integer complexity level from its lower to upper bound. These original question-specific levels are separate from the atomic-operation counts used on the plots’ x-axes. Each of the 74 pairs was tested in both conditions (148 episodes total).

Question: Does tool use increase with the number of atomic operations? See calculate_atomic_operations.py for how atomic operations are calculated for each question type.

Initial takeaways

  • Tool use across complexity ranges: tool-use rate rises from 50% at 5–9 operations (16/32; n=32) to 70% at 10–14 (14/20; n=20), then is 57.1% at 15–19 (4/7; n=7) and 60% at 20–24 (3/5; n=5). Mean calls per episode are 2.19, 4.60, 3.57 and 3.80, respectively. Higher ranges are sparse: 25–29 has 0/1 tool-using episodes, 30–34 has 1/2, and 35–39 has 0/1.
  • Differences across question types: all C-031 (vertex membership after union) and C-101 (vertex-only neighbors of a union) episodes have zero calls. However, 3/5 C-094 episodes (counting vertices lost after union) use tools, so zero tool use does not apply to all union-related tasks. All four C-027 episodes (ordering vertices by distance from a reference vertex) use tools. These are preliminary observations, not established effects.
  • No clear tool-use threshold yet: samples are unevenly distributed across atomic-operation counts, and the highest bins contain only 1–2 items each. See the sample counts in the aggregate plot and table below. Some episodes also hit the token cap before any tool call.

Tool-use measures: an episode uses tools if it emits at least one structured tool call. Each individual call counts once, including failed calls; multiple calls in one model response count separately. Tool mentions in reasoning do not count unless accompanied by an explicit structured tool call.

Atomic-operation counts provide a common complexity measure, although operation types may differ in difficulty.

Scope and next steps

These plots summarize the existing thinking-on pilot. Future sampling could balance the number of examples across atomic-operation levels and include more examples at each level. Where feasible, each level should include multiple question types and diagrams, so it is not dominated by a single question type. The atomic-operation counting rules still need review. Build and validate reference tool programs, then compare actual tool-use sequences to examine strategy efficiency.
